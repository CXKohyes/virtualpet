# 像素宠物屋 · 功能盘点

> **进度以 `README.md`「当前进度」一节为准**，本文件只是某一时刻的快照。
> 上一版这里写着「PRD 里 P0 和 P1 的功能全部做完并验证过」——**那句话是错的**，
> 实际缺了一键启动脚本、动作帧和每日摘要。下面是逐项核实过的版本。

## 已实现

**养成主链路**（PRD 2.1–2.10）

| 模块           | 说明                                                            |
| -------------- | --------------------------------------------------------------- |
| 匿名存档       | `deviceId` → 令牌，只存 SHA-256；刷新/重启后存档还在            |
| 领养命名       | 猫、狗、龙、兔子四选一，名字 1–8 字符                           |
| 五项属性       | 饱食、心情、清洁、精力、健康，0–100 由服务端钳制                |
| 四项照护       | 喂食 / 玩耍 / 清洁 / 睡觉唤醒，各带条件、冷却、经验             |
| 离线衰减       | 懒结算，单次封顶 12 小时；睡觉走另一张衰减表                    |
| 生病与恢复     | 滞回：健康 <30 进入、≥50 解除，30–49 保持原状                   |
| 等级进化       | 10 级、三形态，条件未满足不进化，进化不可逆                     |
| 物种特性       | 猫玩耍收益高、狗照护收益与回血高、龙喂食与精力优势、兔子好动耐脏 |
| 性格台词       | 192 句，按物种×状态/场景，不连续重复                            |
| 精灵图         | 脚本程序化生成 12 张 64×64（4 物种 × 3 形态），固定种子可复现    |
| 音效           | Web Audio 合成 6 种 8-bit 音效，无音频素材                      |
| 适配与可访问性 | 360/768/1440 三档、`prefers-reduced-motion`、键盘焦点、替代文本 |
| 粒子效果       | 六种爆发配方，纯 DOM/CSS，无逐帧 JS 循环                        |

**异步对战**（PRD 2.11，P1）

好友码、发起挑战、宠物快照冻结、服务端确定性自动战斗、逐回合战报、最近对战列表、
WebSocket 通知、物种对战倾向（猫快 / 狗韧 / 龙猛）。战斗不影响养成。

**多宠物槽**（PRD 2.1，P2 第一项，2026-09）

最多 3 只，同一时间只有一只「当前宠物」，`players.active_pet_id` 记录。
名册按槽位升序**逐只结算**，一眼看出谁快不行了；点一下切换，切换会带回结算摘要。
非活跃宠物照常衰减。`DELETE /pets/me` 退役，改成按 ID 送走（不幂等）。

**更多物种**（PRD 2.6、P2，2026-09）

新增第四个物种**兔子**：玩耍心情 +15%、清洁衰减 -30%，对战速度全物种第一（+7）但攻击零加成。
48 句新台词（7 状态 × 3 + 9 场景 × 3），3 张新精灵图。**不需要数据库迁移** ——
`species` 是自由字符串，配置接口由 `Species.values()` 派生。槽位仍是 3，
所以一次养不下全部物种，玩家必须挑（这是有意的取舍）。

**公网部署**（PRD 6.2、TECH_DESIGN 12.3 的一部分）

阿里云 ECS 单机部署：systemd + nginx 同源反代、WebSocket 来源白名单、
接口限流（分档令牌桶）、MySQL 8.0.46。详见 `docs/deployment.md`。

**工程**

15 个 REST 接口 + 1 个 WebSocket 广播 + 2 个 dev 专用接口；
后端 271 项测试 / 前端 180 项；`scripts/acceptance.mjs` 140 项真机验收；
请求级访问日志（PRD 6.6）。

**P2 剩余**

- 账号注册与跨设备同步 —— **评估后搁置**，理由见下
- 道具、食物种类和收集图鉴 —— `TECH_DESIGN` 全文对「道具」零命中，需要新开设计
- ~~更多物种~~ **已实现**（2026-09，新增兔子，共四个物种）；分支进化和季节活动仍未做
- 实时回合制对战、房间、匹配和断线重连
- 多实例 + Redis + STOMP relay（需要先解冻「不使用 Redis」）

> **账号体系为什么搁置**：`PRD.md:336` 规定不收集邮箱和手机号，这同时堵死了密码找回。
> 没有找回通道的密码登录会变成半成品 —— 忘记密码就等于账号在那台设备上永久锁死，
> 比没有账号更难解释。真要做，得先决定是否放宽隐私范围。

**运维欠账**

| 项 | 影响 |
| --- | --- |
| 数据库没有备份策略 | 上一次丢数据是靠 binlog 捞回来的，而 binlog 开着是运气不是策略 |
| 没有 HTTPS/WSS | 卡在 ICP 备案。`PRD.md:297` 要求公网必须 HTTPS，目前是既定偏差 |
| 没有监控告警 | 只有 `/actuator/health` 一个端点 |
| 单实例 | 内存 broker，重启会断掉所有 WebSocket 连接（前端会自动重连） |

**其它已知限制**

| 项                     | 影响                                                                                                              |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------- |
| `virtual_pet_test` 库  | 建了长期没用到（接口测试全在 H2 上），P2 迁移时拿它做过一次真机彩排                                                |
| 同一设备并发首次会话   | 唯一索引会拦下并返回 500。多宠物槽**没有修好它**，只是从 `players` 挪到了 `player_devices` 之外的另一张表上          |
| 战斗平衡两端有偏差     | 中期（5 级）40–60% 已平衡，两端仍有偏差：10 级狗对龙 79%、猫对龙 68%                                            |
| 物种修正字段已饱和     | 6 个字段被猫狗龙占满，兔子只能复用字段换强度组合（玩耍心情 +15%、清洁衰减 -30%），拿不到独占机制                  |
| 健康恢复窗口偏窄       | **这是 PRD 2.3 的设计**（四项都要 >60，而饱食每小时 -5，所以单次结算最多 8 小时）；不是缺陷，但重病宠物需多轮照护 |
| 只在 Chrome + 本机验证 | 没测过真实手机、Safari、触摸操作                                                                                  |
